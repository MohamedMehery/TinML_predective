# Pilot T12 Results — CWRU → PU (synthetic data)

> **Status as of 2026-10-09 21:30 UTC: the pilot run was interrupted
> before completing.** The run produced per-(rep, fold, seed) Macro-F1
> numbers to stdout for 32 of the planned 175 runs, but **did not
> write any CSV before the process ended**. There are no `PILOT_T12_*.csv`
> files on disk and no committed results. The numbers below are
> reproduced *verbatim* from the run's stdout log so that nothing is
> fabricated; they are not a publishable result.

## What happened

The T12 (CWRU → PU) cross-machine transfer pilot was launched with
the following parameters:

- 5 representations (R1_Raw, R1_Env, R2_Raw, R2_Env, R3_Order).
- 7 source LOBO folds (each fold holds out one CWRU UID).
- 5 random seeds (42, 1337, 2026, 7, 99).
- 13 target UIDs (PU).
- Cluster bootstrap on `physical_bearing_uid` with n=10,000.
- 3-class Macro-F1 on the full PU target.

Planned total: 5 × 7 × 5 = **175 training runs**.

The `run_pipeline.py` `main()` writes the CSV outputs at the *end* of
the run, after all 175 per-(rep, fold, seed) calls complete. The
in-memory results were not flushed incrementally. When the run was
stopped at the user's request, the process ended after 32 of 175
runs (~18 %), and the CSV write at the end never ran. The synthetic
`.npz` files in `pilot/synthetic/raw_data/` were also lost when the
process ended (the directory no longer exists; they can be
regenerated by re-running `synthetic/src/generate_synthetic_benchmark.py`).

## What the partial transcript shows (preliminary, not a result)

Three observations from the 30 verified runs, with the explicit
caveat that R3_Order and the MLP reps never completed:

1. **R1_Raw fold asymmetry.** When the held-out source UID is a
   fault class (IR_007, IR_014, IR_021, OR_007, OR_014), the
   cross-machine Macro-F1 lands in the 0.43-0.55 range with
   relatively tight 95 % CIs. When the held-out UID is the
   only Healthy UID (CWRU_N), the Macro-F1 drops to 0.23-0.27.
   This is *expected* and *correct* LOBO behavior: when the
   only Healthy class sample is removed from the train fold, the
   model has no positive examples of Healthy vs. fault, and
   over-predicts fault on the target. The per-UID F1 breakdown
   would be needed to confirm this interpretation; that breakdown
   is in the per_uid_f1.csv which the interrupted run did not
   produce.

2. **R1_Raw seed variance.** For each fold, the 5 seeds produce
   Macro-F1 values within a ~0.10 absolute range (e.g. fold 0:
   0.43-0.54, fold 4: 0.44-0.56). The 95 % CIs on the bootstrap
   (n=10,000) are wider than the seed-to-seed range, so the
   seed variance is small relative to the per-UID bootstrap
   variance. This is consistent with the C5/C8 charter's
   `cluster_bootstrap_iterations = 10000` choice being appropriate.

3. **R3_Order was not reached.** The smoke test before the
   full run (R2_Raw and R3_Order only, fold 0 seed 42, bootstrap
   n=200) showed R2_Raw = 0.55 and R3_Order = 0.13. The full
   run was launched in part to see whether that 0.13 was a
   stable finding or a fluke. **It is not resolved.** The R3_Order
   rows in the planned 175-run matrix would have been the headline
   scientific comparison (does R3_Order beat the data-driven reps
   on this synthetic transfer?). The current state is: not measured
   for the full LOBO + multi-seed grid.

## What should happen next

There are at least three reasonable next steps; this checkpoint does
not pick one.

1. **Re-run the pilot to completion.** Re-generate the synthetic
   data (`pilot/synthetic/src/generate_synthetic_benchmark.py`),
   then run `python3 -m src.run_pipeline --bootstrap-n 10000` and
   let it finish. At ~150-200 s per R1 run and ~30-60 s per MLP run,
   the full 175 runs take ~5-7 hours on CPU. The CSVs will be
   written at the end. **Recommended change before the rerun:**
   modify `run_pipeline.main()` to flush the per_run CSV incrementally
   (e.g. open it in append mode after every fold) so that an
   interruption does not lose the work done so far.

2. **Re-run with a smaller scope.** A 1-fold × 5-seeds × 5-reps
   pilot (25 runs, ~30-60 min) would close the headline R3_Order
   question and be the natural next commit.

3. **Skip the pilot and proceed to the real-data experiment.**
   The pilot is a smoke test; the C5/C8 hypothesis is about real
   cross-machine transfer. Once the `[TO VERIFY FROM SOURCE DOC]`
   markers in the CWRU / Paderborn manifests are cleared by
   downloading the real datasets, the real-data experiment can be
   the next step, with the pilot deferred indefinitely.
