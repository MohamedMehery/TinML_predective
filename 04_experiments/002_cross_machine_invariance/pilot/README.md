# Pilot — Synthetic Cross-Machine Smoke Test

> **CRITICAL — read before running anything that consumes this directory.**
> This pilot uses **synthetic vibration data** generated by a deterministic
> physical-dynamics model. It is a **pipeline smoke test only**, not part of
> the C5/C8 evidence base. Nothing in this directory may be cited as a
> result of Experiment 002.

## Why this exists

The `02_datasets/manifests/cwru.md`, `paderborn.md`, and `seu.md` files
document the **real public CWRU / Paderborn / Southeast University
benchmarks**, verified by the paper matrix (P15, P16, P20, P27, P38, P39).
Those real datasets are not part of this sandbox; they have to be
downloaded by the user from the providers' pages and the
`[TO VERIFY FROM SOURCE DOC]` markers in the per-dataset cards need to
be cleared before `src/preprocess.py` is run against them.

This pilot gives us a way to **verify the end-to-end pipeline shape**
(preprocessing → R1/R2/R3 → 1D-CNN/MLP training → transfer-matrix output)
**before** the real datasets are available, so that when the real data
arrives the only unknowns are the data themselves, not the code path.

## What the synthetic generator does

The script `synthetic/src/generate_synthetic_benchmark.py` implements a
deterministic physical-dynamics model of a rolling-element bearing:

1. **Shaft fundamental + harmonics** at 1X and 2X the rotation frequency.
2. **Fault impulse train** at the characteristic kinematic frequencies
   (BPFO, BPFI, 2×BSF) using the *actual* bearing geometry constants from
   the SKF 6205-2RS (CWRU drive end) and the 6203 (Paderborn 2016 release).
3. **Structural resonance response** modeled as a decaying sinusoid
   impulse response at 3.8 kHz (CWRU casing) or 2.4 kHz (PU casing), with
   physically plausible damping ratios.
4. **Additive Gaussian noise** at a fixed SNR per dataset.

The result is a `.npz` file per (dataset × bearing UID × speed) record,
plus a `pilot_manifest.json` index.

## What the synthetic data is **NOT**

- It is not a measurement. It does not contain real CWRU or PU signals.
- It does **not** validate the C5/C8 hypothesis. The hypothesis is about
  *real* cross-machine transfer; synthetic cross-machine transfer is a
  test of whether the pipeline respects the kinematic-order decoupling
  *as designed into the generator*, not a test of the hypothesis itself.
- It is not part of the paper evidence, the charter, the decision log,
  or the CWRU/PU/SEU manifests. The C5/C8 experiment result is taken
  from `results/`, never from `pilot/results/`.

## How to run

```bash
cd 04_experiments/002_cross_machine_invariance/pilot
python synthetic/src/generate_synthetic_benchmark.py
ls synthetic/raw_data/                   # ~80 MB of .npz files
cat synthetic/manifests/pilot_manifest.json
```

The `.npz` files are written to `synthetic/raw_data/` and are
**git-ignored** (see the repo-root `.gitignore`). Re-running the script
overwrites them deterministically (seed is set per-record), so the
pilot is fully reproducible.

## What the pilot validates

Once `src/preprocess.py`, `src/train.py`, and `src/evaluate.py` exist,
this pilot will be used to verify, in order:

1. **Preprocessing shape contract.** 12 kHz CWRU records → 2,048-sample
   windows at 1,024-sample hop; 64 kHz PU records → resample to 12 kHz
   first, then window. The pilot `.npz` shapes match the real-data shapes
   (CWRU: 120,000 samples at 12 kHz, PU: 320,000 samples at 64 kHz), so
   the windowing math is identical.
2. **IDFT 1X speed tracker convergence.** With known speed in the
   `pilot_manifest.json`, the tracker should converge to within ±1 % of
   the nominal speed on every synthetic record.
3. **R1_Raw collapse expectation.** On the synthetic cross-machine pairs
   (CWRU→PU and PU→CWRU) the 1D-CNN R1_Raw model should drop markedly
   vs. the same-domain control, because the synthetic generator uses
   *different* resonance frequencies (3.8 kHz vs. 2.4 kHz) and *different*
   SNR (6 dB vs. 3 dB) per dataset. This is the "design intent" of the
   synthetic test, and the pilot's job is to verify the pipeline surfaces
   it.
4. **R3_Order stability expectation.** R3_Order should be more stable
   across the synthetic cross-machine pairs than R1_Raw, because the
   fault impulses in the synthetic generator are already shaft-synchronous
   in the angular domain. **If R3_Order is not more stable than R1_Raw on
   the pilot, the pipeline is wrong** — it would invalidate the real-data
   experiment too.

## Where pilot results go

Pilot numbers go to `results/` (this directory) and are explicitly
labeled with the prefix `PILOT_`. They never overwrite or merge with
the real-experiment `results/` in `04_experiments/002_cross_machine_invariance/results/`.
